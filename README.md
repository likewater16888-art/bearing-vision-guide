# 成品轴承视觉检测 · 调试速查站

把《成品轴承操作手册细化版本.docx》（519 节、355 张配图）压缩成**一个可以直接双击打开、3 秒内查到答案**的静态速查页，并附带一套**覆盖全部 519 节的教学训练**（课程 / 抽认卡 / 分维练习 / 抽考 / 错题本）。

- **零依赖**：纯 HTML + CSS + 原生 JS，不用构建、不起服务、不联网，`web/index.html` 双击即用。
- **面向现场**：操作工 / 巡检员 / 工艺员真正会问的问题——"这个缺陷在哪个阶段、哪个相机、哪个参数、往哪边调"。
- **双通道**：结构化速查（结论优先）+ 手册全文（可核对原文），每条结构化结论都能一键跳回原文小节。
- **可考核**：26 课覆盖手册全部 519 节，701 个知识点 / 708 道题，答错自动进错题本，抽考按六维出成绩单。
- **能上手（v1.4）**：12 条「机台上出现这个现象 → 下一步做什么」流程 + 24 道情景题；导航压到 4 个 Tab（现场 / 速查 / 练 / 全文），速查页首屏只留「看什么 / 按这个顺序调 / 别这么做」。

> `git config --global --unset http.https://github.com/.proxy` 与 `git config --global --unset https.https://github.com/.proxy`，推送完再按原值（`http://127.0.0.1:7890`）加回去。

## 2. 四个 Tab 怎么用（v1.4 起导航从 6 个压到 4 个）

| Tab | 回答的问题 | 内容 |
| --- | --- | --- |
| **现场** | 机台上出这个现象，下一步做什么？ | **12 条症状流程**，按 漏检 / 误判 / 定位 / 换型 / 开线 分组：每条都是「按这个顺序做」+ 每步的「为什么」+ 只该动的那几个参数 + 一条红线；页尾可一键跳对应专题 / 案例 / 手册原文 |
| **速查** | 这个工位怎么调？ | 首屏先给 **30 秒结论**（看什么 / 按这个顺序调 / 别这么做），其余全部折叠：检测算法 / 光源方案 / 相机分工 / 典型缺陷 / 阶段成像与检测内容（亮度锚点 + 禁止画面 + 亮度怎么调）/ 成像与亮度调校总则 / 灰度链路（内径）/ 型号 × 阶段矩阵（端面）/ 检测项逐项速查（关键参数推荐值）/ 参数区间表 / 必须记住的规则 / **标准化调参完整流程（手册原版 7 / 8 步 + 44 张步骤配图，每步可跳手册原文）** / 现场常见坑 / 现场问答 / 本工位相关案例 |
| **练** | 我记住了吗？ | 26 课学习路径（= 手册全部 519 节）+ 701 个知识点 + 708 道题：课程练习、今日复习（抽认卡 SM-2 间隔）、分维练习（A 成像 / B 参数 / C 配置 / D 定位 / E 排障 / F 红线 / G 基础）、抽考 30 题（六维配额 + 成绩单 + 补学清单）、错题本；再加 **24 道现场情景题**（答错直接给理由并链到对应流程）。进度存本机 localStorage，可导出 / 导入 |
| **全文** | 手册原话是什么？ | 519 节全文 + 表格内嵌图片，支持标题筛选、上下节跳转；速查页的「手册原文 →」直接落到对应一级章节；每节底部有「练这一节 →」直达该节练习 |

「速查」左侧还有三组入口，不占 Tab 位置：

- **机型 → 两款机型差在哪**：一张表列清真差异（端面阶段数 / 跑马灯频闪归属相机 / 检测张数），最后一行「软件与参数」点明其余完全相同；当前机型那一列高亮。
- **参考 → 产品阶段矩阵**：按产品类型（密封圈轴承 / 防尘盖轴承 / 金属保持架 / 尼龙保持架 / 开式轴承）列出端面阶段与检测内容，避免"产品类型选错导致批量漏检"；同组还有 26 课系统学（`#/learn`）。
- **专题 / 案例 / 参数表**：v1.3 里的独立 Tab，现在收进「参考」组；旧链接 `#/guide/…`、`#/case/…`、`#/gloss`、`#/learn` 全部仍然可用。

## 4. 重建数据（手册更新时）

```powershell
# 0) 原始 docx 未随仓库分发（体积大）：先把《成品轴承操作手册细化版本.docx》放回项目根目录，
#    或改下面 --docx 的路径；也可直接用别人已生成的 web/data/*.js 跳过 1) 2)。

# 1) 解析 docx，抽出文本、表格、图片（需要 Python 3 + Pillow）
python tools/extract_docx.py --docx "成品轴承操作手册细化版本.docx" --out tools/extracted

# 2) 生成网页数据与图片
python tools/build_web_data.py --src tools/extracted --web web

# 3) 自检：字段完整、图片路径、引用章节、案例工位是否合法
node tools/check_web_data.js

# 4) 重建教学数据（课程 / 知识点 / 卡片 / 题库），并自检覆盖率与答案可回溯
node tools/build_learn.js
node tools/check_learn_data.js

# 5) 自检现场流程 / 情景题（步骤是否写了理由、引用的专题与案例是否存在、机型阶段差异是否真的存在）
node tools/check_lite_data.js

# 6)（可选，但改过 app.js / lite.js / knowledge.js / scenarios.js 后建议跑）渲染冒烟：
#    不打开浏览器，用最小假 DOM 跑一遍全部路由 —— 30 秒结论 / 折叠块 / 机型切换阶段数 /
#    机型差异表高亮 / 12 条流程 / 24 道情景题 / 旧链接（#/guide、#/case、#/gloss、#/doc、#/learn）
node tools/smoke_render.js
```

`web/data/knowledge.js` 是**人工维护**的结构化结论（工位、参数、专题、案例、红线），手册改动后按需同步；`manual.js` / `images.js` / `learn.js` 由脚本覆盖生成，不要手改。

## 5. 维护约定

- 新增/修改结论 → 改 `web/data/knowledge.js`，字段含义与数量基线见 `docs/方案说明.md` 第 6 节。
- **加一条现场流程** → 改 `web/data/scenarios.js` 的 `SCEN.flows`，一条流程的字段是：
  `id`（`#/live/<id>` 用）、`cat`（漏检 / 误判 / 定位 / 换型 / 开线 五选一）、`station`（外径 / 内径 / 端面 / 通用）、`title`、`when`（什么现象下来看这条）、`steps[{do, why}]`（`do` = 下一步动作，`why` = 为什么这个顺序）、`params[{k, v}]`（只列真会动的参数，区间照抄参数表）、`stop`（红线）、`guideId` / `caseId`（可选，指向 `KB.guides` / `KB.cases`）。
  改完跑 `node tools/check_lite_data.js`：缺 `why`、引用不存在的专题、类别写错、流程没有配套题都会报错。
- **加一道情景题** → 写进 `SCEN.drills`：`{id, q, opts[3], a（正确下标）, why, flow（必须有对应流程）}`；选项顺序在页面里按 `id` 稳定打乱，所以正确项不要刻意放第一位。
- **给工位上「30 秒结论」** → 在 `knowledge.js` 对应工位加 `lite: { see, tune, stop }`；**给阶段标机型专属** → 在阶段上加 `m: "m6"`（只属于 6 工位）或 `m: "m8"`，速查页与侧栏阶段数会按机型过滤。
- **改渲染层（`app.js` / `lite.js` / `style.css`）之后**：先跑 `node tools/smoke_render.js`。它用最小假 DOM 跑全部路由，红了通常是某个路由渲染为空、`LITEUI` 没导出、或机型切换没真的改变阶段数——比开浏览器逐页点快得多。
- 手册原文变化 → 重跑第 4 节前三步，检查 `check_web_data.js` 是否全绿，再刷新页面。
- 数值口径冲突时**以设备实测成像为准**，但与手册不一致的点必须在 `KB.meta.note` 或对应参数说明里写清楚。
- 图片只允许通过管线产出（统一 webp、宽度 ≤1200），不要手工往 `web/images/` 里塞图。

## 6. 已知限制

- 静态站点：数据更新必须重跑管线，没有后台和权限体系。
- 搜索是归一化子串匹配 + 分词「与」逻辑，没有分词词典和同义词扩展（如「暗斑/脏点」需分别搜）。
- 全文视图对超长表格采用横向滚动，手机端需要左右滑。
- 结构化知识库是手册的**提炼**，不是全文索引；条款级细节仍以「全文」视图为准。
- 教学模块（v1.3）目前是 **P0**：题目以「判据 / 参数区间 / 检测项归属 / 流程步序 / 案例根因」为主，题型全是单选（含图片判读题）。v1.4 补上了 **P1 的现场版**——12 条症状流程 + 24 道情景题（答错给理由并链回流程），但仍**没有**完整决策树分支（同一现象下的多机型 / 多产品细分只写在流程正文里）与 **P2 参数沙盘**（不能调参数看成像变化）；进度只存本机浏览器，清缓存或换机器会丢，需用「学习记录 → 导出 / 导入」搬。
- 题库由 `build_learn.js` 从手册与知识库**派生**，正确选项必定能在原文找到（`check_learn_data.js` 逐题校验），但干扰项是从同章节其他结论里取的，个别题目区分度一般，建议每季度人工抽查 20 题。
